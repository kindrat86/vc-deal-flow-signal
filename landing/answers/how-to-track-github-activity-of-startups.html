How to track GitHub activity of startups: the analyst's guide

Direct answer: Track the organization, not the announcement feed. Pull commit velocity, contributor growth, and repository expansion for watchlist orgs weekly, in identical 14-day windows, from the public GitHub REST API. Measured on a fixed panel, breakout teams become visible 21 to 47 days before their round is announced.

Why analysts track GitHub at all

Most sourcing inputs are narratives: a founder pitch, a press cycle, a referral. GitHub activity differs in three ways. It is public, so everyone starts from the same data. It is timestamped, so you measure change instead of asking about it. And it is behavioral: teams cannot fake weeks of merged work the way a landing page is redesigned in an afternoon. It is not a crystal ball, but it is one of the few pre-announcement inputs an analyst can audit.

Honest caveat: many startups keep their core product private, so public activity is a sample, not the full record. Track organizations on a panel over time rather than judging a single repo snapshot: the change in public behavior carries the signal.

The three things worth tracking

  • Commit velocity. Merged work per org in 14-day windows, read as percentage change against the prior window. Two consecutive accelerating periods filter out one-off bursts such as a hack week or a single large import.
  • Contributor growth. New engineers appearing in the org, and how concentrated commit share is across them. A team going from 3 to 9 active contributors is staffing up, and hiring almost always precedes a raise.
  • Repository expansion. New repositories, new services, and new languages appearing under the org. Expansion means new product surface, which usually means new spend that needs funding.

Each metric is noisy alone; together they separate teams genuinely accelerating from teams that merely look busy.

The manual path, step by step

  1. Fix a watchlist. Pick your population once: sectors, stages, regions. A fixed panel is what makes week-over-week rankings comparable. GitDealFlow's panel is 350+ venture-backed startup GitHub organizations across 15 sectors, refreshed weekly.
  2. Pull weekly from the public API. The GitHub REST API needs no special access for public orgs. Fetch org-level repos and contributor activity on the same day each week, into the same schema.
  3. Measure identical windows. Score every org on the same 14-day cadence so a rising team shows up as a rank change, not a vibe.
  4. Demand confirmation. Act only on two-period acceleration. Single-window spikes are the most common false positive in signal sourcing.
  5. Review the exceptions. Read top movers before acting: a bulk import or monorepo migration can look like acceleration to a script.

Where manual tracking breaks down

For five orgs, a weekly script and a spreadsheet are enough. Past that, four failure modes arrive together. API rate limits cap how many orgs you can sweep in a window. Orgs rename, archive, and split repositories, which corrupts your time series unless you reconcile identities. Maintainers change and the weekly pull quietly stops. And the measurement windows drift, so the ranking stops meaning anything. This maintenance, not the initial script, is the actual cost of the signal.

What the data shows, honestly

Answers on this site are anchored to one public dataset: engineering activity across 350+ startup GitHub organizations in 15 sectors, refreshed weekly from the public GitHub REST API. Across that panel, breakout engineering teams become visible 21 to 47 days before their round is announced. Be honest about what that is: a leading indicator, not a guarantee. Most teams that accelerate still fail, and some strong fundraisers never show top-quartile public velocity. The value is in ranking attention weeks before the announcement, while the founder still has time to talk.

Frequently Asked Questions

How do I track a startup's GitHub activity?

Watch the organization, not a single repository: track commit velocity in 14-day windows, new contributors joining, and repository expansion (new repos, services, and languages). Pull weekly from the public GitHub REST API or a panel tracker, comparing identical windows so change reads as a rank change, not noise.

What GitHub metrics indicate a startup is about to raise?

No metric predicts a raise. The honest framing is that engineering acceleration often precedes announcements: commit velocity, contributor growth, and repository expansion tend to ramp before a round. Across the tracked panel, breakout engineering teams become visible 21 to 47 days before their round is announced. Treat it as a leading indicator for ranking attention, not a guarantee: most accelerated teams still fail.

Can I track startup GitHub activity manually, or do I need a tool?
