# Guest-Essay Outlines — Seeding the "Code-Side Sourcing" Category — 2026-05-30

**Goal:** get *other people* to use the term **Code-Side Sourcing** and link the canonical definition at
`signals.gitdealflow.com/code-side-sourcing`. Every external use = a relevance-perfect editorial backlink +
a co-citation + brand-search lift. Category-creation is the single best off-page lever a faceless brand has.

**Anonymity-safe:** the *idea* and the *data* carry the byline ("The Data Nerd"); no face, no personal LinkedIn,
no HN/Reddit/PH (per standing rules). Each essay is genuinely useful, not a product pitch — that's what gets it
accepted and re-cited.

**Voice:** tool not a fund · lead with the job · plain language · "momentum" only as a precise methodology term,
never the hook.

## Essay A — "Warm intros don't scale. Code-side sourcing does." (flagship category essay)

- **Best homes:** Data Driven VC (Andre Retterath), Not Boring, a seed-fund blog, Sacra.
- **Length:** 2,000–2,500 words.
- **Thesis:** The dominant deal-sourcing methods — warm intros, decks, databases, generic alt-data — all fire
  *after* a company decides to raise. There's an earlier, public, leading indicator: what the team ships on
  GitHub. Name it: **code-side sourcing** — public repository-velocity data as a leading indicator of
  venture-stage outcomes.
- **Spine:**
  1. The sourcing stack today and why each rung is late (warm-intro → deck → database → generic alt-data).
  2. The public signal that leaks before the deck: shipping cadence, contributor influx, repo expansion.
  3. The three properties that make it a *category*, not a hack: public input · pre-deck signal · published
     methodology.
  4. Evidence: SSRN panel (n=219), 21–47-day median lead time; one worked example with the honest caveats.
  5. Five first principles (accel over absolute · two-period confirmation · contributor breadth · classification
     over scoring · open methodology).
  6. When it *fails* (closed-source teams, infra-light products) — credibility through honesty.
- **The single link:** "the category is defined here → /code-side-sourcing". One link, in context, mid-essay.
- **Why it earns the link:** it gives the publication a *named framework* their readers will repeat.

## Essay B — "What your startup's GitHub activity tells investors before you pitch" (engineer-facing)

- **Best homes:** The Pragmatic Engineer, a dev-tools newsletter, an eng-leadership blog.
- **Length:** 1,500–2,000 words.
- **Angle flip:** written for the people *generating* the signal, not investors.
- **Spine:**
  1. Your public GitHub footprint is already being read as a market signal — here's how.
  2. The specific patterns investors infer (cadence, contributor growth, release pulse) — plain English.
  3. What you can and can't control about it; what's noise.
  4. The methodology, openly (link to /methodology + SSRN), so it's not a black box.
  5. Honest limits — this is a signal, not a verdict.
- **The single link:** /code-side-sourcing as "the framework investors are using to read this".

## Essay C — "The alt-data playbook came to venture — and it's free" (investor/strategy-facing)

- **Best homes:** Newcomer, The Generalist, a strategy newsletter.
- **Length:** 2,000 words.
- **Thesis:** Public markets industrialized alt-data (satellite, cards, web-scrape). Venture's version —
  public engineering velocity — is sitting in the open, free, and underused. Code-side sourcing is the wedge.
- **Spine:**
  1. The alt-data arc in public markets → the venture parallel.
  2. Why GitHub is the cleanest public venture signal (it's where the work *is*, pre-marketing).
  3. The methodology + the dataset (open, DOI, weekly) — show, don't tell.
  4. Implications for how seed/Series-A sourcing changes.
- **The single link:** /code-side-sourcing + the open dataset.

## Outreach mechanics

- **Pitch alongside the data-drop email** (don't double-send) — the data-drop *is* the proof the essay is real.
- **Lead with the reader benefit**, not "I'd like to write for you": "I could give your readers a named framework
  + open data — here's the outline."
- **Offer exclusivity** of the angle per publication (don't pitch the same essay to two competitors).
- **One link only**, in context. Stuffing links gets essays rejected and dilutes the signal.

## Lower-effort category-seeding (no editor approval needed, still anonymity-safe)

- Answer genuinely-asked questions on Stack Exchange / Quora ("how do VCs find startups before they raise?")
  with a substantive answer that uses + links the definition once. **Not** Reddit/HN/PH (banned).
- Get **"code-side sourcing"** referenced (even unlinked) in one existing reference article on deal sourcing —
  an unlinked co-citation still teaches engines the entity.
- Cite the term consistently in every owned surface (already done in llms.txt / citations) so external writers
  have a canonical phrasing to copy.
