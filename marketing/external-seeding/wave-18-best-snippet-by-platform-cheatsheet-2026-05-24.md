# Wave 18 Best Snippet by Platform — Cheat Sheet

Purpose
- make platform choice fast
- keep wording native to the channel
- stop overlong replies and wrong proof links

Core rule
Same insight, different platform shape.
Do not paste the same wording everywhere.

## X / Twitter
Best when:
- you need one sharp contrast
- you’re replying inside an active thread
- brevity is an advantage

Best snippet styles
1. Timing line
Most tools help with verification. The useful edge is noticing what changed before the story gets crowded.

2. Momentum line
For technical startups, the interesting signal is rarely raw commit count. It’s the pattern behind shipping intensity, contributor growth, and visible build activity.

3. MCP line
Useful MCP question: can your agent query real startup signal data without private API friction?

Best link types
- TV
- SEM
- MCP

## Reddit
Best when:
- the thread has enough context to reward a slightly longer reply
- you need to answer literally first
- the audience dislikes obvious promotion

Best snippet styles
1. Timing explanation
The cleanest distinction I’ve found is timing vs verification. Most databases are useful once the company is already visible. If the real question is “what changed before the round got crowded?” the earlier clue is often public engineering movement, not another profile page.

2. Momentum explanation
One thing I keep noticing: the public story usually shows up later than the operating signal. For technical startups, you can sometimes see momentum in shipping pace and contributor growth before the outside narrative fully catches up.

3. Non-technical investor translation
The part investors often miss is that the signal is not “read the code.” It’s “notice when public engineering behavior starts changing in a way that matters.”

Best link types
- TV
- SEM
- GHA
- ALT

## Hacker News
Best when:
- the thread is technical
- you have one specific data point or distinction
- you can keep it sourced and compact

Best snippet styles
1. Timing vs verification
The useful distinction here is timing vs verification. Most tools tell you what already happened. The harder problem is noticing what changed before the round becomes obvious.

2. GitHub signal framing
For technical startups, public engineering movement can become visible before the familiar story surfaces catch up. The key is not raw commit count. It’s the pattern behind contributor growth, shipping intensity, and visible build activity.

3. MCP framing
For agent-native VC research, the interesting thing is not just “has MCP.” It’s whether the agent can query structured startup-signal data that matters before the story fully hardens.

Best link types
- methodology
- TV
- SEM
- MCP

## LinkedIn
Best when:
- you need slightly more explanation
- investor workflow / operator workflow context exists
- bullet formatting helps

Best snippet styles
1. Alt-data workflow framing
A good alternative-data workflow for angels is usually smaller than people think:
- one leading signal layer
- one verification layer
- more complexity only when process justifies it

2. Non-technical investor framing
For non-technical angels, the useful translation is simple:
- faster shipping
- more contributors
- more visible build activity
You are not learning to code. You are learning to notice earlier public movement.

3. Output-shape framing
The thing I keep coming back to is output shape. If the weekly read still feels like work, the signal layer is failing.

Best link types
- ALT
- GHA
- REPORT

## Indie Hackers
Best when:
- the thread rewards reflection or builder insight
- the angle is category / process / timing rather than product

Best snippet styles
1. Pattern opener
I keep seeing the same pattern: for technical startups, the public operating signal shows up before the public story does. That does not mean “more data.” It means a calmer read on timing.

2. Distinction opener
I’d separate “what helps verify” from “what helps notice change early.” Those are different jobs and most startup tools blur them.

Best link types
- SEM
- TV

## GitHub / MCP directories / runtime issues
Best when:
- thread is about use case fit
- you need to show why this belongs in a runtime ecosystem
- the audience cares about structured data and workflow fit

Best snippet styles
1. MCP fit
If the use case is VC research rather than generic web search, the useful question is whether the MCP server returns structured startup signal data with no private auth overhead.

2. Agent-native research framing
For technical startup sourcing, the main split is between broad research stacks and earlier signal stacks.

Best link types
- MCP integration page
- agent runtimes page

## Email / media pitch
Best when:
- you want one clean angle, not a post
- recipient is a newsletter, reporter, or podcast host

Best snippet styles
1. Media distinction
Most startup tools help with verification, while the harder problem is noticing what changed before the round gets crowded.

2. Category thesis
Startup engineering momentum as an earlier public signal for technical startups.

3. Podcast angle
Alternative data tools are usually framed as “more data,” but the more useful distinction is “timing vs verification.”

Best link types
- TV
- SEM
- ALT
- methodology

## If you only remember one rule
- X = one sharp sentence
- Reddit = answer first, link second
- HN = one sourced distinction
- LinkedIn = 2-4 clean lines
- IH = pattern insight
- GitHub/MCP = use-case fit
- Email = one angle, one link
