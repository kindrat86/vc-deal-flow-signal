# Wave 18 Send / Don't Send Decision Tree — 2026-05-24

Purpose
- stop low-quality posting
- reduce over-sending and wrong-page sending
- make a yes/no decision fast before every outreach action

Rule
If the context is weak, do nothing.
If the context is strong, send one useful thing.

========================================
Step 1 — Is there real context?
========================================

Ask
- is the person already discussing sourcing, startup signal, GitHub, alt data, workflow, or MCP?
- is the thread relevant enough that your reply would help even if the product did not exist?

If NO
- do not post
- log nothing or mark as waiting

If YES
- go to step 2

========================================
Step 2 — What is the real question?
========================================

If the real question is:
- timing vs verification -> send TV
- startup engineering momentum -> send SEM
- GitHub for non-technical investors -> send GHA
- GitHub as sourcing surface -> send GDF
- alt-data stack -> send ALT
- Crunchbase difference -> send CBA
- practical output -> send REPORT
- methodology / rigor -> send METH
- agent-native use -> send MCP

If you cannot identify the real question
- do not send a link yet
- reply with one sentence only, or wait

========================================
Step 3 — Which platform is this?
========================================

X
- keep to one sharp line
- link only if it is proof for the exact sentence

Reddit
- answer the thread literally first
- then add the proof link if needed

HN
- one sourced distinction
- never sound promotional

LinkedIn
- 2-4 lines max
- bullets okay

GitHub / MCP issue
- use-case fit first
- product second

Email / media
- one angle
- one reason their audience should care
- one link only

========================================
Step 4 — Should you send homepage, methodology, report, or cluster page?
========================================

Send homepage only if
- they explicitly want the main entry point
- they are not skeptical and just need the front door

Send methodology if
- they ask for rigor
- they challenge the method
- they want formal proof

Send report if
- they ask what it looks like in practice
- they need output-shape proof
- they are skeptical but open

Send cluster page if
- the thread is about a precise distinction
- the question matches one page exactly
- you want the strongest category framing

========================================
Step 5 — Should you send more than one link?
========================================

Default
- no

Only send a second link if
- they explicitly ask for more
- the first link solved one layer but exposed a second specific question

Never send
- homepage + methodology + report all at once
- product menu dumps
- “here are 5 useful pages” in a first touch

========================================
Step 6 — Should you follow up?
========================================

Public reply
- if no response, do not force a follow-up immediately
- wait 24–48h only if it makes sense and there is a natural continuation

Direct outreach
- if no response, wait 72h before follow-up

If response is positive but vague
- send one clean proof page only

If response is skeptical
- narrow the claim once
- do not argue

========================================
Step 7 — Hard don't-send conditions
========================================

Do not send if:
- the thread is hostile bait
- you are trying to “tick the box” without context
- you only have a product pitch and no useful distinction
- you are about to send the same wording you already used elsewhere today
- you are tempted to explain the whole stack in one message

========================================
Fast decision table
========================================

Question / context -> Send
- “How do you find startups early?” -> TV
- “What is startup engineering momentum?” -> SEM
- “I’m not technical” -> GHA
- “What does it actually look like?” -> REPORT
- “What’s the methodology?” -> METH
- “How is this different from Crunchbase?” -> CBA or TV
- “What’s the best alt-data stack?” -> ALT
- “Can an agent use this?” -> MCP

If still unsure
- investor context -> TV
- technical context -> SEM
- skeptical context -> REPORT or METH
- agent context -> MCP

========================================
Best single sentence if you need one
========================================

Most tools help with verification. The useful edge is noticing what changed before the story gets crowded.
