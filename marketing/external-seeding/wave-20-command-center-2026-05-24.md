3. Best snippets by platform
========================================

X
- Most tools help with verification. The useful edge is noticing what changed before the story gets crowded.
- For technical startups, the interesting signal is rarely raw commit count. It’s the pattern behind shipping intensity, contributor growth, and visible build activity.
- Useful MCP question: can your agent query real startup signal data without private API friction?

Reddit
- The cleanest distinction I’ve found is timing vs verification. Most databases are useful once the company is already visible. If the real question is what changed before the round got crowded, the earlier clue is often public engineering movement, not another profile page.
- One thing I keep noticing: the public story usually shows up later than the operating signal.
- The part investors often miss is that the signal is not “read the code.” It’s “notice when public engineering behavior starts changing in a way that matters.”

HN
- The useful distinction here is timing vs verification. Most tools tell you what already happened. The harder problem is noticing what changed before the round becomes obvious.
- Raw GitHub activity is noisy. The useful part is the pattern, not the raw stream.
- For agent-native VC research, the interesting thing is not just “has MCP.” It’s whether the agent can query structured startup-signal data that matters before the story fully hardens.

LinkedIn
- A good alternative-data workflow for angels is usually smaller than people think.
- For non-technical angels, the useful translation is simple: faster shipping, more contributors, more visible build activity.
- The thing I keep coming back to is output shape. If the weekly read still feels like work, the signal layer is failing.

========================================
4. Send / don't send quick rules
========================================

SEND if
- there is a real live context thread
- you can identify the exact question
- you can answer in one sentence
- you know the exact page to send

DO NOT SEND if
- no real context exists
- you are about to force the product into the conversation
- you need more than one link to explain yourself
- you are tempted to send homepage by default
- you are reacting emotionally to skepticism
