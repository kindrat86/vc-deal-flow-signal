# Wave 25 Maintenance Cadence — External Seeding System

Purpose
- keep the outreach operating system alive after the build phase
- define what gets reviewed daily, weekly, and monthly
- stop the system from becoming stale documentation

Core rule
Do not add more assets unless the current system fails in real use.
First use the system. Then patch the weakest layer only.

Daily (10–15 min)
1. Open `wave-21-first-live-week-activation-2026-05-24.md`
2. Check top 3 active targets for real context
3. If a real context-rich thread exists, send one sentence and one page
4. Update `wave-14-response-scoreboard-2026-05-24.md` immediately
5. Fill the minimal section of `wave-16-daily-rollup-template.md`

Weekly (30–45 min)
1. Review `wave-14-response-scoreboard-2026-05-24.md`
2. Move stale rows to follow-up-due if needed
3. Fill `wave-16-weekly-outcome-review-template.md`
4. Promote one winning snippet/page combination
5. Demote one weak snippet/page combination
6. Refresh the top 3 targets in `wave-21-first-live-week-activation-2026-05-24.md` if needed

Monthly (45–60 min)
1. Re-read `wave-22-master-index-2026-05-24.md`
2. Archive anything obviously superseded
3. Patch any cheat sheet that repeatedly causes bad page choice or bad snippet choice
4. Update the Dream 100 execution board with new priorities
5. Review whether the content cluster itself needs a new page based on repeated objections

If a Tier-1 opportunity appears
1. Open `wave-23-tier1-opportunity-runbook-2026-05-24.md`
2. Open `wave-17-tier1-rapid-response-pack-2026-05-24.md`
3. Log the thread URL in the scoreboard
4. Respond inside 4 hours
5. Review the interaction in the daily rollup the same day

If the operator has only 15 minutes
- use `wave-23-15-minute-runbook-2026-05-24.md`

If the operator has 60 minutes
- use `wave-23-60-minute-runbook-2026-05-24.md`

If someone replies and asks for more
- use `wave-17-target-response-playbook-2026-05-24.md`
- use `wave-17-result-type-follow-up-matrix-2026-05-24.md`
- use `wave-15-follow-up-variants-2026-05-24.md`

Red flags that mean the system needs patching
- homepage keeps being sent first when a sharper page exists
- operators keep sending multiple links in first touch
- methodology gets sent when the person asked for sample output
- sample report gets sent when the person asked for rigor
- repeated replies sound pitchy or defensive
- scoreboard stops being updated same day

Success signs
- one-page selection gets faster
- fewer words per reply, better fit
- more asks for methodology, sample, or differentiation
- clearer weekly understanding of which page/snippet/platform actually works

End state
The system is healthy when it is boring:
- operators know where to look
- page choice is fast
- snippet choice is fast
- logging is automatic
- weekly learning is real
